# Feature Spec: Employee Management Module

*(Part 1 of 2 — build this first. Part 2, the HR Document Generator, plugs into this later and is a separate spec.)*

---

## 1. Summary

Replace the current single-page **"Add Team Member"** form with a proper **Employee Management** system: a multi-step onboarding wizard, a full employee profile with photo/documents/payroll, and an archive for former employees. This becomes the single source of truth for employee data — the future HR Document Generator will read from it, not duplicate it.

---

## 2. What's Changing vs. Today

The current form (Personal Information / Role & Department / Bio — see existing screenshot) only captures name, contact info, job title, department, hourly rate, start date, and a bio. It's missing:
- A profile photo
- Legal/ID documents
- Full salary structure (only a flat hourly rate today)
- Banking/payroll details
- Any persistent "profile" to view an employee's full record after creation
- Any distinction between active and former employees

This spec fixes all of that while keeping the exact same visual language (dark navy sidebar, purple/gold accents, card-per-section layout, rounded gray inputs, sticky right-side action panel).

---

## 3. Multi-Step "Add Employee" Wizard

Replace the single page with a **5-step wizard**. Keep the current card style and sticky sidebar (Status + Add/Cancel buttons); add a **stepper** at the top of the main card area, e.g.:

`1 Personal → 2 Employment → 3 Documents → 4 Payroll → 5 Review`

Numbered circles connected by a line; active step highlighted in the same gold used today for the "Add Member" button.

### Step 1 — Personal Information
- **Profile photo** upload (circular preview, drag-and-drop or click-to-upload) — reused later on the profile page and on any generated documents
- Full Name *
- Date of Birth
- Gender
- Email Address *
- Phone Number
- National ID / Passport Number *
- Nationality
- Home Address
- Emergency Contact (name, relationship, phone)

### Step 2 — Employment Details
*(mostly what exists today, kept)*
- Job Title / Role *
- Department (dropdown)
- Employment Type (Full-time / Part-time / Contractor / Intern)
- Manager / Reports To (dropdown of existing employees — needed later for approval workflows, so build the field now even if nothing uses it yet)
- Start Date
- Work Location (Office / Remote / Hybrid)
- Status — see Section 6 below for the full status list and logic (this replaces the current simple Active/Inactive dropdown)

### Step 3 — Documents & Files
Upload slots, each with a label, required/optional flag, and file preview thumbnail:
- National ID / Passport scan *
- Signed Employment Contract *
- CV / Resume
- Educational Certificates (multi-file)
- Professional Certifications (multi-file)
- Other (multi-file, user-labeled)

Each upload shows filename, upload date, and a delete/replace icon. Style: same rounded, light-gray box as the text fields, dashed border + upload icon when empty, thumbnail + filename when filled.

> This is the same file store that a future HR Document Generator module will read from and write generated certificates into — see Section 7 (Data Model) so the schema is ready for that without rework.

### Step 4 — Payroll & Banking
*(new)*
- **Salary structure** — build this as line items, not one flat number, since payroll/HR documents downstream need a breakdown:
  - Basic Salary *
  - Housing Allowance
  - Transport Allowance
  - Other Allowance(s) — add as many labeled line items as needed
  - Gross Total (auto-calculated, read-only)
  - *(Keep Hourly Rate as an alternate mode via toggle, for contractors/part-time who aren't salaried)*
- Bank Name
- Account Number / IBAN
- Tax ID / Social Security Number (if applicable in your jurisdiction)
- Payment Method (Bank Transfer / Cash / Cheque)
- Currency

### Step 5 — Review & Confirm
- Read-only summary of all 4 previous steps, grouped by card, each with an "Edit" link that jumps back to that step.
- Final **"Add Employee"** button (same orange CTA style as today).
- **Cancel** discards the wizard.
- See Section 6 for what happens if required documents/fields are missing at this point.

## 4. Employee Profile Page

Every employee gets a permanent profile page (opened by clicking their row in the Team list), with tabs:

| Tab | Contents |
|---|---|
| **Overview** | Photo, name, title, department, status, contact info, start date — Steps 1–2 in read/edit mode |
| **Documents** | Uploaded personal files from Step 3 (ID, contract, CV, certs). *(A second sub-section for HR-generated certificates gets added here once that module is built — leave room in the layout for it.)* |
| **Payroll** | Salary structure and bank details from Step 4. *(A "Generate Payslip / Salary Certificate" shortcut button gets added here later — no need to build it now.)* |
| **Timeline / Activity** | Chronological log: hired, edited, status changes, documents uploaded — see Section 7 audit log |

## 5. Status Field & Lifecycle Logic

Replace the current simple Active/Inactive dropdown with these statuses:

- **Draft / Incomplete** — wizard started but not finished
- **Pending Documents** — record created, but required documents/fields are missing
- **Active** — fully onboarded
- **On Leave**
- **Terminated / Departed** — moves to archive, see Section 6

### Wizard drafts & the "Active" gate

- **Auto-save drafts**: every time the user moves to the next step (or every ~30 seconds while typing), silently save progress. If they close the tab, the record persists as **Draft / Incomplete** and can be resumed later from a "Drafts" filter on the Team page.
- **Block "Active" until required items are present**: the starred (*) fields — Full Name, Email, Job Title, National ID Number, National ID/Passport scan, Signed Employment Contract.
  - If any are missing, the record can still be saved, but status is forced to **"Pending Documents"** instead of "Active."
  - HR sees a visible reminder (badge/count on the Team page, e.g., "3 employees pending documents").
  - Once the missing items are added (from the Employee Profile page, any time — not just during the wizard), HR is prompted to confirm and the status flips to Active.
  - This keeps onboarding fast (nothing blocks creating the record) while preventing a fully "Active" employee from existing without the paperwork that documents/payroll later depend on.

## 6. Former Employees Archive

- New sidebar sub-view/tab under **Team**: **"Old Employees"**.
- Setting an employee's status to `Terminated` / `Departed`:
  - **Disables their login/account access immediately** (if employees have portal accounts).
  - **Keeps their profile, all uploaded files, and all future generated documents fully intact** — nothing is deleted.
  - **Removes them from the main active Team list** and moves them to the "Old Employees" archive.
- The archive is searchable/filterable the same way as the active list (name, department, last role).
- Their profile page still works the same, with an "Archived — [date]" badge instead of "Active," and employment/payroll fields become view-only (documents can still be generated from this record later, once that module exists — don't disable that at the data layer, just don't build the UI for it yet).
- **Reactivation** (e.g., rehire) should be supported — moves them back to the active list and re-enables login.

## 7. Data Model

- **`employees`** table: id, personal info fields (Step 1), employment info fields (Step 2), payroll info fields (Step 4, including structured salary line items), status, photo_url, manager_id (self-referencing FK), created_at, updated_at.
- **`employee_files`** table: id, employee_id (FK), category (`id_doc` / `contract` / `cv` / `certificate` / `other`), file_url, uploaded_at, uploaded_by.
- **Audit log** (`employee_activity` or similar): id, employee_id (FK), action_type (created / edited / status_changed / file_uploaded), performed_by, timestamp, notes. Powers the Timeline tab (Section 4).
- Leave room in the schema for a future `hr_documents` table (employee_id FK) — don't build it now, just don't design anything that would conflict with adding it later (e.g., don't hardcode "Documents tab = employee_files only" in a way that can't later union with another table).
- Deleting/deactivating an employee is **soft-delete only** — the `Terminated` status change, never a hard delete — for legal/audit reasons.

---

## 8. Permissions

- Only users with HR/Admin role can access Add Employee, edit employee records, or view the Old Employees archive (respect existing role-based access control).
- Regular team members (if they have logins) should at most see their own Overview/Documents tabs, not other employees' payroll data.

---

## 9. Visual Notes (match existing screenshot)

- Keep the dark navy sidebar, purple/gold accent, card sections with icon + bold heading, and the sticky right-hand panel exactly as-is.
- Stepper sits where the "Add Team Member" title currently is, or just below it.
- File upload slots use the same rounded, light-gray box style as text fields — dashed border + upload icon when empty, thumbnail + filename when filled.
- Employee Profile page top banner: photo (circular, larger than in the wizard), name, title, and status badge, styled like the existing "Personal Information" card.
- "Old Employees" archive list uses the same table/list style as the current Team list, just with a muted/grayscale visual treatment to distinguish it from active employees at a glance.
